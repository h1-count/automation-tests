# 工作流基线

生效日期：2026-08-26。当前调试期唯一可写工作流为 `v1`，版本由 `CURRENT_WORKFLOW_VERSION` 固定，且在每个 request 创建时随定义图和 `request-policy-v1` 冻结。

`request-policy-v1` 只记录本次请求的设计入口（复用、增量或全量）、交付目标、评审速度/模式/风险、是否写入数据和选中用例范围。命令、状态、门禁与成本报告读取这份冻结策略，不重新交叉推断路径。

本次硬切换终止并删除旧运行档案、运行时元数据、评审缓存、迁移命令和兼容解析。旧 request 不迁移、不回放；需要继续测试时，使用稳定套件和当前资料新建 v1 request。稳定套件、来源、测试脚本和 Git 提交历史不属于本次清理范围。

调试期可以停止旧实例并删除其实现，避免多版本规则不断叠加。进入生产期后，如需让在途实例完成，才应为每个历史版本保留精确且只读的执行路径。

## 工程契约规则

当前工作流内的所有工程契约固定命名为 `*-v1`。版本号只标识调试期基线，不用于区分请求、稳定套件、授权路径或评审结构：这些差异必须由显式枚举字段表示。正式执行 Manifest 使用 `scope`，执行授权使用 `mode`，两者均只允许 `request` 或 `stable_suite`；字段与该枚举不一致时必须拒绝。任何 `*-v2` 及以上工程标识、旧格式解析、兼容别名或多版本联合类型都不属于当前基线。
