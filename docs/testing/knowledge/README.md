# 项目测试经验库

本目录保存纳入 Git 的**项目测试经验**。每个被测项目独立维护一个 `<project>-testing-knowledge.md` 文件，避免将开放平台、App、MQTT 或其他项目的经验混用。

它与 `sources/knowledge-base/` 的原始知识资料库职责不同：原始资料库保存可追溯的业务事实和原文；本目录只记录经受控探索、正式执行或报告复盘验证后可复用的测试策略。两者冲突、原始资料版本变化或证据不足时，以当前测试请求在 `plan.md` 中确认的原始资料和结论为准。

## 使用规则

- 任务开始时，先由用户测试需求确认被测项目，再读取当前项目对应的知识文件；用户长期协作偏好仍读取 `.local/testing-memory.md`。代码仓库定位属于用例确认后的工程层，不用于替代项目确认。
- 项目测试经验只记录已验证且可复用的流程、环境约束、恢复策略、失败归因、定位或脱敏策略；不得复制需求正文、协议字段说明、接口契约或产品规则。此类事实应保留在 `sources/` 并通过 `manifest.yaml` 追溯。
- 每条经验采用“适用范围 → 观察 → 判断 → 下次优先策略”；观察来自原始资料时，记录对应 manifest `id`，但不复制原文。
- 未验证候选保留在 Git 忽略的 `.local/project-knowledge-candidates/<project>.json`；计划只引用 `CAND-<编号>`，不得复制候选正文或把候选写入本目录。候选取得受控探索或正式执行验证证据后，或发现时已具备该证据时，可直接写入本目录；报告阶段只复盘提升、合并、放弃和剩余候选。资料明确的手机号格式、验证码阈值、OAuth 分支等需求事实仍保留在 `sources/` 和 `REQ → RULE → caseId`，不属于项目经验。
- 严禁记录账号、密码、验证码、Cookie、Token、密钥、完整生产地址、设备唯一标识、真实用户信息或敏感业务数据。
