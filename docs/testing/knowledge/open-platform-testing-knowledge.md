# 开放平台项目测试经验

> 本文件纳入 Git，记录本项目当前可复用的测试经验，每条经验明确标注“待验证 / 已验证”证据状态。同范围新策略覆盖当前条目，旧版由 Git 历史保留。原始平台事实、协议和接口契约保留在 `sources/knowledge-base/` 并通过 `manifest.yaml` 追溯；本文件不复制原文，也不替代正式规则、测试用例、报告或执行证据。当前用户行为偏好仅记录在 `.local/testing-memory.md`。

## 2026-07-16：登录与注册页的语义定位

- 适用范围：开放平台 test 环境的 `/login` 页面，且仅限不提交登录或注册的基础交互验证。
- 观察：登录和注册使用可访问的 `tab`/`tabpanel`；登录字段可按 ARIA 名称定位，注册字段可按 placeholder 定位；注册提交按钮的实际可访问名称为“同意条款并注册”。
- 判断：这些语义定位可替代动态组件 ID 和坐标；提交前禁用状态可在不发送验证码、不上传文件或提交数据的前提下验证。
- 下次优先策略：优先使用 `getByRole('tab')`、`getByRole('textbox', { name })` 和 `getByPlaceholder()`；注册提交按钮使用“同意条款并注册”，执行短信、上传或提交前仍需单独授权。

## 2026-07-13：开放平台配网方式决策

- 适用范围：开放平台创建或配置 IoT 产品，特别是 WiFi 设备。
- 观察：配网方式受芯片、固件、厂商和设备形态约束；页面右侧“查看详情”提供联网方式、配置项、配置选项及说明。仅因测试产品而选择 `mi-SoftAP`、`zennze-SoftAP` 等厂商专属方案没有依据。
- 判断：未知设备芯片、固件或厂商协议时，不能猜测或随意选择 SoftAP/BLE 专属方案。
- 下次优先策略：先查看配网方式详情，再检索可用知识库；若仍无法确认设备约束，默认选择“设备二维码绑定”。已确认 ESP32、门锁、厂商协议或网关能力时，才选择相应专属方案。

## 2026-07-13：开放平台账号密码登录的安全挑战恢复

- 适用范围：开放平台测试环境的账号密码登录会话初始化。
- 观察：登录提交后可能出现滑块安全挑战；挑战完成后还可能出现后续验证输入或需要再次提交的页面状态。
- 判断：不能将“滑块完成”直接等同于“登录成功”，也不能在单次人工操作后结束浏览器会话。
- 下次优先策略：使用“自动填写与提交 → 识别挑战或登录成功 → 人工仅完成安全挑战 → 自动重新观察 → 自动完成可确定的填写与提交 → 登录态校验”的状态机；仅在出现新的安全挑战时再次请求人工。

## 2026-07-13：开放协议产品的功能定义前置条件

- 适用范围：开放协议接入产品完成基础配置后，进入“功能定义”阶段。
- 观察：页面先要求选择该品类的产品功能模板，再编辑功能。平台知识库将物模型分为属性（Properties）、事件（Events）和方法（Methods）；模板中的必选功能不可编辑或删除，非必选和自定义功能可编辑或删除。
- 判断：功能模板和物模型会直接影响后续设备开发与高级配置，不能在未知设备能力时随意选定模板或自定义功能点。
- 下次优先策略：先从设备功能、通信协议与实际能力确认模板；仅将已确认支持的开关状态、控制命令和事件定义为功能点。需要切换模板时，先确认，因为“重新选择”会覆盖已有产品功能定义。

## 2026-07-13：开放协议产品开发与产品测试边界

- 适用范围：开放协议接入产品在功能定义后的设备开发、高级配置和产品测试阶段。
- 观察：设备开发提供 MQTT 协议资料、设备授权码、产品凭证、设备注册与固件 OTA 管理；高级配置的场景联动和消息推送为可选项。产品测试要求先在 App 中对设备配网、控制和 OTA 等完成自测，再可预约官方实验室；认证通过后产品才可申请正式上线。
- 判断：获取授权码、注册真实设备、查看或使用产品凭证、上传固件、预约实验室及申请上线均会消耗资源、暴露敏感信息或产生外部业务影响，不能作为常规探索动作。
- 下次优先策略：受控探索仅确认入口、前置条件和可见状态，不读取、复制、记录或展示产品凭证；真实设备动作、固件上传、实验室预约和上线申请必须得到单独明确确认。没有测试需求时，保持高级配置的可选项不配置。

## 2026-07-13：开放平台固件配置的测试边界

- 适用范围：开放平台的产品固件配置与 App 固件信息展示。
- 观察：该阶段的固件配置是将固件包与版本信息保存至云端；App 读取并展示可用的最新固件信息。实际下载安装和设备端升级由用户在 App 中主动触发。
- 判断：固件包上传、云端版本记录和 App 最新版本信息同步属于平台配置与信息展示验证，不等同于设备 OTA、设备控制、MQTT 上报或设备状态回归。
- 下次优先策略：本项目当前范围仅覆盖固件配置页面的输入、保存与版本信息，以及 App 对最新版本信息的可见性；不在此范围内注册设备、配网、控制设备、上报 MQTT、下载固件或点击升级。稳定测试固件上传的执行授权见后续“稳定固件测试数据的上传授权”。

## 2026-07-13：含 SDK 固件版本表单

- 适用范围：开放协议直连产品的“设备开发 → 固件配置”。
- 观察：页面提供“含 SDK 固件版本列表”和“新建版本”。新建表单的固定固件类型为“含 SDK 固件”，必填字段为固件名称（最多 32 字符）、固件版本、上传生产固件、测试 OTA 固件版本、上传测试固件；版本说明为可选项（最多 100 字符）。固件版本字段提示格式为 `1.0.2`，且测试 OTA 固件版本必须大于生产固件版本；前端文件控件允许所有文件类型，具体限制以服务端结果为准。列表展示固件名称/固件 key、固件版本、固件状态、测试 OTA 固件版本、版本说明、上传时间和操作。
- 判断：当前固件配置至少需要两份包及两套版本信息；不能把单一固件文件或设备端 OTA 流程误当作该页面的完整输入。
- 下次优先策略：页面路径和唯一语义定位由自动化受控探索后固化到脚本中，不放入 `.env.example`；一次性测试产品、两份固件包路径和版本仅在实际执行时由用户上传附件或指定本机路径提供。稳定测试固件上传的执行授权见后续“稳定固件测试数据的上传授权”。

## 2026-07-14：稳定固件测试数据的上传授权

- 适用范围：测试环境中开放平台“含 SDK 固件”版本配置。
- 观察：用户确认版本化固件包属于稳定测试素材；上传只创建云端测试版本记录，对真实设备无影响，App 是否下载和升级仍由用户另行触发。
- 判断：在已确认的测试计划、用例和脚本方案内，可以自动上传 `test-assets/firmware/` 中的稳定测试固件生成测试数据；不需要逐次动作前确认。
- 下次优先策略：脚本保留 `ALLOW_OPEN_PLATFORM_FIRMWARE_UPLOAD=true` 显式运行门禁，限定测试环境；禁止生产环境、设备注册、设备端下载/升级、设备控制和 MQTT 操作。

## 2026-07-14：固件版本创建未完成的诊断

- 适用范围：测试环境中“含 SDK 固件”新增版本表单。
- 观察：两份稳定固件文件上传后页面显示文件与大小；生产版本 `1.0.1`、测试 OTA 版本 `1.0.2` 已满足已知的递增规则。点击“确定”后对话框仍打开、无字段错误，重新进入页面的版本列表仍无数据。
- 判断：当前证据不足以区分前端未发起创建请求、服务端隐含兼容性规则或成功后的页面状态未同步；不能宣称版本创建成功，也不能仅据 HTTP 200 判定通过。
- 下次优先策略：保留为 `UNKNOWN`，要求确认新增版本接口契约、固件兼容性和发布状态；复测前继续使用字段标签范围内的上传 input 定位，避免依赖动态 input ID。

## 2026-07-13：登录认证产物脱敏

- 适用范围：包含账号、密码、验证码或会话的 Web 登录测试。
- 观察：失败页面产物可能携带表单输入或认证状态。
- 判断：常规 Trace、截图、视频和详细错误上下文存在敏感信息风险。
- 下次优先策略：认证流程默认关闭可能回显输入的 Trace、截图和视频；本地会话仅存入 Git 忽略且最小权限的认证目录，报告只记录脱敏结果与文件存在性。

## 2026-07-14：创建产品页 Element Plus 单选控件定位

- 适用范围：开放平台 `/integration/product/create` 的设备类型和通讯方式选择。
- 观察：原生 `radio` 输入在可访问性树中可见，但 Playwright 直接对该输入执行 `check()` 时，可能被同一组件的可见 `span.ep-radio__inner` 遮挡并导致指针操作超时。
- 判断：此处不是业务前置条件或权限失败；应通过与单选项关联的可见父容器触发选择，再以 `radio` 的已选中状态断言结果，不能使用坐标点击或 `force` 绕过。
- 下次优先策略：按可访问名称定位目标 `radio`，点击其关联父容器，然后断言该 `radio` 为 checked；继续使用语义定位，不依赖动态 class、坐标或索引。

## 2026-08-04：开放平台注册短信验证码的页面内人工接管

- 经验编号：EXP-9A6554D32CD4
- 适用范围：开放平台注册短信验证码的页面内人工接管
- 证据状态：待验证
- 观察：开放平台注册发送短信前可能存在图形安全挑战，短信验证码只能由用户在同一可见浏览器会话内输入，脚本不得读取或持久化验证码。
- 当前优先策略：正式脚本最多点击发送一次并等待倒计时成功状态，再有界等待用户直接在注册验证码输入框填写，填写完成后自动继续；Runner强制headed且超时禁止重发。
- 证据引用：tests/web/open-platform/account-access-20260803/registration-submit.formal.spec.ts
- 验证条件：完成一次受控正式注册执行，证明发送不重复、页面输入后自动继续、超时不重发且所有产物不含验证码。
