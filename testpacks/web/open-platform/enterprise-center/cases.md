# 用例集：开放平台企业中心（enterprise-center）

> 测试类型：Web ｜ 默认环境：test ｜ 默认数据策略：no_write
>
> 上下文来源：`sources/indexes/open-platform.yaml`、`sources/open-platform/需求/AIoT平台项目.docx`（「企业/企业信息/成员管理/添加成员/编辑成员/删除成员」章节）、前端源码 `web-open-platform/src/pages/console/company/CompanyInfo.vue`、`MemberManagement.vue`、`src/pages/console/components/BtnEditMember.vue`、`BtnTransferCompany.vue`、`src/components/layouts/console/ConsoleHeader.vue`、`src/support/recordGeneratedData.ts`、`experience/general.md`、`experience/open-platform.md`；查重比对 console-home 包（企业切换入口/权限刷新已覆盖）、account-center 包（所属企业列表/转移入口已覆盖）。
>
> 上下文结论：①企业信息页为纯只读回显（企业名称/标识/ID/邮箱/地址 + 三系统开通状态），状态随激活企业联动（queryOPSystemStatus 按 corpId 查询）；②成员管理页仅管理员可见添加/删除入口，自身行操作列显示「-」（不可自删），管理员行无勾选框，搜索支持关键字（姓名/手机号）+权限筛选；③添加成员弹窗：姓名 2~20 字符、手机号 11 位（非数字字符被剔除、mobile 校验）、备注 ≤64 字符、权限树必选（「请至少选择一项权限。」）——因此无法经 UI 构造「零权限成员」，无权限空态走「未加入企业」路径；添加成员无验证码环节，可全自动执行；④写入序列设计：OP-ENT-006 在**受限企业**添加成员 M1（全新合成手机号 13000000002，避开 TEST_PHONE_SECOND 的在途注册申请），OP-ENT-008 删除 M1（二次确认），OP-ENT-010 以同手机号重新添加实证需求「成员已有账号→不新建账号、开通企业权限」分支——结束时 M1 仍为受限企业成员，供后续补测轮以成员身份登录执行 account-center 包「成员行退出企业入口与二次确认」与 console-home 包「未加入企业空态」两条待转正用例；⑤台账：成员生成数据经 `src/support/recordGeneratedData.ts`（新增 recordGeneratedMemberData）记入本包 `runtime/generated-data.json`（只增不删，删除/重添以同 runId 覆盖标记）；⑥测试账号为两家企业的企业管理员，企业切换经头部下拉（console-home 011 已验证切换与恢复）。
>
> 范围外声明：非管理员视角的成员管理页（无添加/删除入口、操作列「-」）——需成员账号登录视角，随「成员行退出企业入口与二次确认」补测轮一并执行；删除管理员自身——UI 层对自身行不渲染删除入口（OP-ENT-003 断言覆盖其形态），alert「禁止删除自身」路径不可达；批量删除成员——与本包删除成员同一 API（batchDeleteUser），单删已覆盖核心链路，批量勾选留待成员数据充足时补测；企业信息编辑——页面为只读回显，无编辑入口（需求未定义企业信息编辑）；成员管理分页——当前单人/双人数据不足一页，分页行为留待数据充足时补测。
>
> 本表供测试范围审核。真实密码、Token、密钥、Cookie 等可复用凭据仅从本地 `.env` 或对应登录态存储读取；测试手机号、成员姓名/备注均为合成值，可正常出现在记录、报告与 trace 中。
