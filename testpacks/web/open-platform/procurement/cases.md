> 测试类型：Web ｜ 默认环境：test ｜ 默认数据策略：no_write（本包全部 no_write，写入链路见范围外声明）
>
> 上下文来源：`sources/open-platform/需求/产品接入系统功能需求说明/产品接入系统功能需求说明.md`（「采购管理」章节）、前端源码 `web-open-platform/src/pages/integration/procurement/Procurement.vue`、`components/BtnCreateProcurement.vue`（采购申请表单 267 行：10 字段校验规则逐一核对）、`components/BtnShowProcurement.vue`、`api/integration/procurement.ts`（queryModulelList → /product/develop/plan/config）、`api/integration/integration.ts`（queryProductSelectListExtend → /product/select/list）、`src/utils/ValidationRuleBuilder.ts`（realname/mobile/email/address/length 规则）、`experience/general.md`、`experience/open-platform.md`；查重比对 product-testing（预约表单校验在彼包覆盖）、authcode（授权码表单在彼包覆盖）。
>
> 上下文结论：①采购列表：采购类型/采购状态筛选 + 产品名称或Model搜索 + 表头 11 列；2026-09-03 实证列表为空（/product/module/purchase/list totalCount=0）；②采购申请表单字段与校验（源码核对）：申请人 required realname（2-32，show-word-limit）；手机号 required mobile（11 位定长）；邮箱 email 格式（可空）；收货地址 required address（8-64，show-word-limit）；采购类型 radio required（字典 S_PROCUREMENT_PURCHASE_TYPE，排除 freeModule）；产品 select required（/product/select/list 返回当前账号 3 个 direct 产品）；模组类型 radio required + 模组型号 select required（queryModulelList 按 developType+configId 查询，**direct 返回空 → 「未查询到可用的模组信息」**）；采购套数 InputNumber min=1 max=999999 默认 1；备注 length(5,100)；③提交：客户端校验失败 → 字段级提示 + 弹窗不关闭 + 无网络写入（doConfirm return false）；成功 toast「采购申请提交成功」；④申请企业/申请人/手机号/邮箱从会话预填；⑤免费领取（isFree）入口仅在模组接入产品开发页，台账产品均 direct 不适用。
>
> 范围外声明：**采购申请写入**（模组采购仅适用模组接入产品；台账 3 个产品均协议直连、模组列表为空，必填模组类型/型号无法选择，写入链路被业务规则阻塞——2026-09-03 探针实证；OP-PROC-007 以客户端拦截断言覆盖该限制的行为面，创建模组接入合成产品后可另行设计写入用例）；**免费领取模组**（入口在模组接入开发页，同上）；**采购详情查看**（列表无数据行；有数据后补）；**采购状态流转**（依赖供应商处理）。
>
> 本表供测试范围审核。真实密码、Token、密钥、Cookie 等可复用凭据仅从本地 `.env` 或对应登录态存储读取；非法值均为合成构造（D01~D08），提交被客户端拦截、无网络写入。
