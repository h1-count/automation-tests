# 用例集：开放平台创建产品

> 测试类型：Web ｜ 默认环境：test ｜ 默认数据策略：登录会话写入，产品创建仅在标注用例中执行
>
> 上下文来源：
> - `sources/open-platform/需求/产品接入系统功能需求说明/产品接入系统功能需求说明.md`（“产品开发首页 P0”与“创建产品 P0”章节，行 152–311）
> - `experience/general.md`、`experience/open-platform.md`
> - `node scripts/load-test-context.mjs --project open-platform --scope create-product` 输出清单
>
> 上下文结论：
> - 创建产品为三步向导：①选择产品类别（一级/二级品类，单选必选）②选择智能化方式（免开发接入/模组SDK接入/开放协议接入/云云接入，按品类显示）③完善产品信息（产品名称 ≤60 字符且无标点空格、产品型号小写字母/数字 ≤6 字符、设备类型按开发方式限定、产品描述 ≤200 字符）。
> - 入口为产品开发首页【创建产品】按钮；创建成功后生成产品 model（企业标识+品类英文+产品型号），状态“开发中”。
> - 原型包未包含创建产品页面，页面细节（步骤控件文案、校验时机）需在审核后经 Chrome DevTools MCP 探索确认，相关用例脚本状态标注“待页面探索”。
> - `.env` 已配置 `TEST_PHONE`、`TEST_VERIFICATION_CODE`（无已存认证状态文件），登录采用短信验证码方式，会话在用例结束后失效。
> - 真实密码、Token、密钥、Cookie 等可复用凭据仅从本地 `.env` 或对应登录态存储读取；测试手机号、测试验证码为合成值，可正常出现在记录、报告与 trace 中。

## 参数化数据

<details>
<summary>D01｜唯一合成产品资料</summary>

| 字段 | 生成规则 | 示例形态 |
| --- | --- | --- |
| 产品名称 | `自动化测试产品` + 运行时间戳数字（≤60 字符、无标点空格、企业内唯一） | 自动化测试产品1788150000000 |
| 产品型号 | `at` + 4 位随机数字（小写字母/数字、≤6 字符、同品类内唯一） | at1234 |
| 设备类型 | 固定选择“普通设备” | 普通设备 |
| 产品描述 | `自动化测试生成的产品` + 运行时间戳（≤200 字符） | 自动化测试生成的产品1788150000000 |

> 品类与智能化方式在用例中固定为一个支持全量设备类型的组合（如“照明-灯”+“开放协议接入”），实际取值以页面探索结果为准。

</details>
