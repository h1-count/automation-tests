# 开放平台控制台首页：测试结论

## 当前结论（2026-09-03 首轮建立）

- 用例集 11 条（no_write 全覆盖），实现 10 条可执行 + 1 条 fixme（OP-CONS-010）。上下文来源：需求 docx「AIoT控制台/系统入口」章节、控制台原型、前端源码（Home.vue / sys-data.ts / ConsoleLayout.vue / ConsoleHeader.vue / routes）与探索实证；详情见 cases.md 顶部。
- 控制台首页实现 = 「用户信息卡 + 按权限过滤的系统入口列表」，无表单无写入，本包全部 no_write；需求/原型中的「数据概览、快捷入口」未在当前实现中出现，以源码实现为测试依据。
- 2026-09-03 探索实证（storageState 只读探索脚本，快照与截图见 `runtime/exploration/out/`）：
  - 测试账号名下两家企业：完整权限企业（3 系统入口）与受限企业（仅产品创建权限，**仅显示产品接入系统入口**）；企业切换后入口随权限刷新，用户卡企业名同步。
  - 三入口跳转实测：产品接入 → `/integration/product`（路由重定向落点 `/integration/product/management`）、产品运营 → `/device/management`、产品服务 → `/service/aiot-develop`；与源码 switchSystem 映射一致。
  - 服务支持下拉 = 文档中心/技术工单/常见问题；用户下拉 = 账号中心/退出；企业切换当前值与激活企业一致；首页无侧边菜单与面包屑；未登录直达 /console/home 重定向登录页（与 login-register OP-AUTH-022 一致）。
- 登录态策略（与 create-product 包同模式）：优先复用本包 `runtime/auth-state.json`，其次复用 create-product 包共享会话；均失效时短信登录自愈（人工点选图形验证码，登录功能本身由 login-register 包覆盖）。会话有效时全包零人工、零写入。
- OP-CONS-010（无任何系统权限空态）转范围外：两家测试企业均含产品接入权限，无法构造空态；脚本以 `test.fixme` 保留覆盖意图。空态文案的两处疑似错别字（「您没还有获得系统使用仅限」「您没还有加入任何企业」，源码静态发现）保留为缺陷候选，待获得无权限账号后实证注解。

## 断言策略说明

- 本包以「行为 + 可观察终态」断言为主：URL 跳转、列表条目集合、控件可见性、文本非空/精确值（企业名同步为精确断言）；无提示类断言场景（无表单校验）。
- OP-CONS-004 入口集合用精确相等断言（3 项及顺序）；受限企业切换（011）步骤 2 用集合精确断言 `["产品接入系统"]`，并以渲染信号硬等会话刷新（不用固定 sleep）。

## 已知差异与限制

- `/integration/product` 存在路由重定向（落点 `/integration/product/management`），用例预期已按实测事实修正（005/011 步骤 1/4）。
- 受限企业切换会改变会话激活企业（服务端上下文），OP-CONS-011 结束时**必须切回原企业**（脚本已内置恢复步骤并出「会话恢复」注解），否则会影响 create-product 等其他功能包的执行前提。
- dev server 卡顿窗口与路由 chunk 冷启动延迟：探索首轮曾把「导航在途」误读为「跳转失败」（2.5s 短窗口），v2 改 `waitForURL` 长等待后三入口全部确认；脚本沿用「渲染信号硬等 + 20s 快速失败重载」对策。
- 项目 element-plus 命名空间为 `ep`（下拉菜单/选项类名前缀 `.ep-`），定位一律 ARIA 优先（`getByRole("option")` 等），类名仅作容器锚点。

## 后续关注

- 空态文案错别字（静态发现）：建议前端核对「您没还有获得系统使用仅限，请向企业管理员申请。」与「您没还有加入任何企业，请向企业管理员申请。」两处文案。
- 若后续提供「无任何系统权限」的成员/企业账号，可将 OP-CONS-010 的 fixme 转正实证空态。
- 控制台外壳（ConsoleHeader/ConsoleLayout）的菜单过滤逻辑较复杂（account/company 子页互斥过滤），企业中心/账号中心包设计用例时需参考本包探索结论。
